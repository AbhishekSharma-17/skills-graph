# DSPy — Optimizers (Compilers / Teleprompters)

> Source: https://dspy.ai/learn/optimization/optimizers — Written for DSPy v2.5.x

## Overview

Optimizers (historically "teleprompters" in DSPy) are the *compilers* that turn a default module into an optimised version by searching over prompts, few-shot demos, or model weights given a **trainset** and a **metric**. They are the single biggest quality lever DSPy provides.

The general shape is always the same:

```python
from dspy.teleprompt import SomeOptimizer

opt = SomeOptimizer(metric=my_metric, <optimizer-specific-args>)
compiled = opt.compile(student=program, trainset=trainset, valset=valset)
```

`compile` returns a new program with the optimised state baked in. The original is left untouched (as long as you don't pass `inplace=True` where supported).

## Which optimizer should I use?

| You have | Use | Why |
|----------|-----|-----|
| ≤ 10 examples, want a quick win | `LabeledFewShot` | Just drops your labels in as demos |
| 10–100 examples, want bootstrapped demos | `BootstrapFewShot` | Generates and filters traces |
| 100+ examples, need best accuracy | `MIPROv2` | Jointly optimises instructions + demos |
| Instruction-only rewriting | `COPRO` | Iteratively rewrites the instruction |
| Enough budget to fine-tune weights | `BootstrapFinetune` | Generates data and fine-tunes the LM |
| Search + sampling | `BootstrapFewShotWithRandomSearch` | Same as `BootstrapFewShot` but tries multiple candidate programs |

Start cheap (`BootstrapFewShot`), move up only if you hit a ceiling.

## Preparing a trainset

Optimizers expect `dspy.Example` rows with explicit input fields:

```python
import dspy

trainset = [
    dspy.Example(
        question="What is the capital of France?",
        answer="Paris",
    ).with_inputs("question"),
    dspy.Example(
        question="Who wrote Hamlet?",
        answer="William Shakespeare",
    ).with_inputs("question"),
    # ... 20–200 rows minimum
]
```

The `with_inputs(...)` call is essential — without it, DSPy treats *every* field as an input, including your label, and the optimizer will memorise the answer rather than learn to predict it.

Split into train / dev:

```python
import random
random.seed(0)
random.shuffle(trainset)
train, dev = trainset[:150], trainset[150:200]
```

## Defining a metric

A metric is a Python callable `(example, prediction, trace=None) -> bool | float`:

```python
def exact_match(example, pred, trace=None) -> bool:
    return example.answer.strip().lower() == pred.answer.strip().lower()
```

See `05-metrics-evaluation.md` for richer metrics (LLM-as-judge, composite scores, etc.).

## BootstrapFewShot

Generates demos by running the *unoptimized* program on the trainset, keeping only the traces whose outputs satisfy the metric, and using those as few-shot examples for subsequent calls.

```python
from dspy.teleprompt import BootstrapFewShot

opt = BootstrapFewShot(
    metric=exact_match,
    max_bootstrapped_demos=4,   # demos generated by the program itself
    max_labeled_demos=16,       # demos taken directly from trainset
    max_rounds=1,               # bootstrap iterations
    max_errors=5,               # halt if too many failures
)

compiled = opt.compile(program, trainset=train)
```

Cheap, fast, and surprisingly effective. Your first compile should almost always be this.

## BootstrapFewShotWithRandomSearch

Runs `BootstrapFewShot` multiple times with different random seeds, evaluates each candidate on a held-out set, and returns the best. Better accuracy, more LM calls.

```python
from dspy.teleprompt import BootstrapFewShotWithRandomSearch

opt = BootstrapFewShotWithRandomSearch(
    metric=exact_match,
    max_bootstrapped_demos=4,
    num_candidate_programs=8,
    num_threads=4,
)
compiled = opt.compile(program, trainset=train, valset=dev)
```

## MIPROv2 — the heavy hitter

Multi-prompt Instruction Proposal Optimizer v2: jointly searches over instructions *and* demos using a Bayesian optimization strategy. Best quality, highest LM budget.

```python
from dspy.teleprompt import MIPROv2

opt = MIPROv2(
    metric=exact_match,
    auto="medium",            # "light" | "medium" | "heavy"
    num_threads=8,
)

compiled = opt.compile(
    program,
    trainset=train,
    valset=dev,
    max_bootstrapped_demos=4,
    max_labeled_demos=4,
    requires_permission_to_run=False,  # otherwise prints a budget warning
)
```

`auto` presets control the number of candidate programs and trials:
- `"light"` — ~10 min / a few dollars for a small pipeline.
- `"medium"` — the sweet spot for most production tasks.
- `"heavy"` — serious budget; use when you've already validated the pipeline design.

## COPRO — instruction-only

If you want to keep demos static (e.g. curated by hand) and only rewrite the instruction, use `COPRO`:

```python
from dspy.teleprompt import COPRO

opt = COPRO(metric=exact_match, breadth=10, depth=3, init_temperature=1.4)
compiled = opt.compile(program, trainset=train, eval_kwargs={"num_threads": 4})
```

## BootstrapFinetune — weight tuning

Generates training data from a teacher program, uses it to fine-tune the student LM, and returns a new compiled program that calls the fine-tuned model. Supports OpenAI fine-tuning and local HF fine-tuning through the configured provider.

```python
from dspy.teleprompt import BootstrapFinetune

opt = BootstrapFinetune(metric=exact_match)
compiled = opt.compile(
    student=program,
    teacher=program,                # can be a stronger model
    trainset=train,
    target="openai/gpt-4o-mini",   # fine-tune base
)
```

Expensive and platform-dependent — prefer prompt optimisation first.

## Using a separate teacher model

Most optimizers accept `teacher=` to use a stronger (expensive) model for generating demos while the compiled program runs on a cheaper model. This is the "distillation" pattern.

```python
teacher = dspy.ChainOfThought(program.signature, lm=dspy.LM("anthropic/claude-opus-4-6"))
opt = BootstrapFewShot(metric=exact_match)
compiled = opt.compile(student=program, teacher=teacher, trainset=train)
```

## Saving and loading compiled programs

```python
compiled.save("program.json")

# In production:
program = MyProgram()
program.load("program.json")
```

The file stores the optimised instructions, selected demos, and field configurations. LM credentials are **not** persisted — configure the LM separately at load time.

## Common pitfalls

- **Forgetting `.with_inputs(...)`.** Optimizers will silently use label columns as inputs; quality will be unchanged from baseline.
- **Metric that returns 0 for everything.** Bootstrapping needs positive signal. Loosen the metric (lowercase, strip, substring match) at compile time, then tighten it at eval time.
- **Compiling MIPROv2 on a tiny trainset (<30 rows).** The Bayesian search has no signal and the result is worse than `BootstrapFewShot`. Start with `BootstrapFewShot` until you have enough data.
- **Reusing a compiled program across unrelated tasks.** Compiled demos are overfit to the trainset's style; recompile for each distribution shift.
- **Running the optimizer without `num_threads`.** Default is 1 — add threads for a 4–8× wall-clock speedup.
- **Not shuffling the trainset.** If your rows are sorted by label, demos will be biased. Always shuffle first.
- **Compiling against the same split you evaluate on.** Use a clean held-out testset that the optimizer never sees.
