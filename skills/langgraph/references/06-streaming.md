## Streaming Basics

LangGraph exposes `stream()` (sync) and `astream()` (async) methods that yield outputs as iterators. Streaming is essential for responsive AI applications — showing progress as agents think and act.

```python
config = {"configurable": {"thread_id": "t1"}}

# Basic streaming
for chunk in app.stream({"messages": [...]}, config):
    print(chunk)

# Async streaming
async for chunk in app.astream({"messages": [...]}, config):
    print(chunk)
```

## Stream Modes

Control what data is streamed using the `stream_mode` parameter:

| Mode | Description | Use Case |
|------|-------------|----------|
| `"values"` | Full state snapshot after each step | Debugging, state inspection |
| `"updates"` | Only changed keys from each node | UI updates, efficient rendering |
| `"messages"` | Token-by-token LLM output | Typewriter-style chat UIs |
| `"custom"` | User-defined data via `StreamWriter` | Progress bars, status updates |
| `"checkpoints"` | Checkpoint events | Monitoring persistence |
| `"tasks"` | Task start/finish events | Job tracking |
| `"debug"` | Combined checkpoints + tasks | Full observability |

### Values Mode

```python
for chunk in app.stream(inputs, config, stream_mode="values"):
    # chunk = full state dict after each node
    print(chunk["messages"][-1].content)
```

### Updates Mode

```python
for chunk in app.stream(inputs, config, stream_mode="updates"):
    # chunk = {node_name: {updated_keys}}
    for node, updates in chunk.items():
        print(f"Node '{node}' updated: {list(updates.keys())}")
```

### Messages Mode

```python
for chunk in app.stream(inputs, config, stream_mode="messages"):
    # chunk = (message_chunk, metadata)
    msg, metadata = chunk
    if msg.content:
        print(msg.content, end="", flush=True)
```

## Token-by-Token Streaming

Stream individual tokens as they're generated by the LLM:

```python
for chunk in app.stream(inputs, config, stream_mode="messages"):
    message, metadata = chunk
    
    # Filter by node name
    if metadata["langgraph_node"] == "agent":
        if message.content:
            print(message.content, end="", flush=True)
    
    # Or filter by tags
    if "final_answer" in metadata.get("tags", []):
        print(message.content, end="", flush=True)
```

**Node that enables token streaming:**

```python
def agent_node(state: State):
    # LLM must be invoked in a way that supports streaming
    response = model.invoke(state["messages"])
    return {"messages": [response]}
```

The LLM provider handles token-level streaming automatically when using `stream_mode="messages"`.

## Custom Data Streaming

Emit arbitrary data from within nodes using `StreamWriter`:

```python
from langgraph.config import get_stream_writer

def processing_node(state: State) -> dict:
    writer = get_stream_writer()
    
    writer({"status": "Starting processing..."})
    
    for i, item in enumerate(state["items"]):
        result = process(item)
        writer({
            "progress": f"{i+1}/{len(state['items'])}",
            "current_item": item,
        })
    
    writer({"status": "Processing complete"})
    return {"processed": True}
```

**Consuming custom streams:**

```python
for chunk in app.stream(inputs, config, stream_mode="custom"):
    if "progress" in chunk:
        update_progress_bar(chunk["progress"])
    elif "status" in chunk:
        show_status(chunk["status"])
```

### StreamWriter Injection (Python < 3.11 Async)

For async functions on Python < 3.11, inject writer as a parameter:

```python
from langgraph.types import StreamWriter

async def my_node(state: State, writer: StreamWriter) -> dict:
    writer({"status": "working..."})
    result = await async_operation()
    return {"result": result}
```

## Multiple Stream Modes

Combine modes by passing a list:

```python
for chunk in app.stream(inputs, config, stream_mode=["updates", "custom"]):
    # chunk structure depends on mode
    # Use v2 format for easier disambiguation
    pass
```

**With v2 format (recommended for multiple modes):**

```python
for chunk in app.stream(inputs, config, stream_mode=["updates", "custom"], version="v2"):
    if chunk["type"] == "updates":
        node_updates = chunk["data"]
        print(f"Node update: {node_updates}")
    elif chunk["type"] == "custom":
        custom_data = chunk["data"]
        print(f"Custom: {custom_data}")
```

## Subgraph Streaming

Stream events from nested subgraphs:

```python
for chunk in app.stream(inputs, config, subgraphs=True, version="v2"):
    namespace = chunk["ns"]  # Tuple identifying the subgraph
    
    if not namespace:
        print(f"Parent graph: {chunk['data']}")
    else:
        print(f"Subgraph {namespace}: {chunk['data']}")
```

The `ns` field is a tuple of subgraph identifiers, enabling you to track which level of nesting produced each event.

## v2 Format

The v2 streaming format provides a unified structure:

```python
for chunk in app.stream(inputs, config, version="v2"):
    # Every chunk has:
    # chunk["type"]  — stream mode name
    # chunk["ns"]    — namespace tuple (empty for root graph)
    # chunk["data"]  — the actual data
    pass
```

**v2 invoke return:**

```python
result = app.invoke(inputs, config, version="v2")
print(result.value)       # The graph's return value
print(result.interrupts)  # List of Interrupt objects (if any)
```

## Async Streaming

### Basic Async

```python
async for chunk in app.astream(inputs, config):
    process(chunk)
```

### Async Events Stream

```python
async for event in app.astream_events(inputs, config, version="v2"):
    kind = event["event"]
    if kind == "on_chat_model_stream":
        token = event["data"]["chunk"].content
        print(token, end="", flush=True)
    elif kind == "on_tool_end":
        print(f"\nTool result: {event['data']['output']}")
```

## Common Patterns

### Chat UI with Streaming

```python
async def stream_response(user_message: str, thread_id: str):
    config = {"configurable": {"thread_id": thread_id}}
    inputs = {"messages": [{"role": "user", "content": user_message}]}
    
    async for chunk in app.astream(inputs, config, stream_mode="messages"):
        msg, metadata = chunk
        if metadata["langgraph_node"] == "agent" and msg.content:
            yield msg.content
```

### Progress Tracking

```python
for chunk in app.stream(inputs, config, stream_mode=["updates", "custom"], version="v2"):
    if chunk["type"] == "custom":
        data = chunk["data"]
        if "progress" in data:
            print(f"\rProgress: {data['progress']}", end="")
    elif chunk["type"] == "updates":
        node = list(chunk["data"].keys())[0]
        print(f"\nCompleted: {node}")
```

### Human-in-the-Loop with Streaming

```python
async for chunk in app.astream(
    inputs, config,
    stream_mode=["messages", "updates"],
    version="v2",
):
    if chunk["type"] == "messages":
        msg, _ = chunk["data"]
        display_token(msg.content)
    elif chunk["type"] == "updates":
        if "__interrupt__" in chunk["data"]:
            interrupt_info = chunk["data"]["__interrupt__"][0].value
            user_response = await get_user_input(interrupt_info)
            # Resume in a new stream call
            break
```

## Common Pitfalls

1. **Using `invoke()` when streaming is needed** — `invoke()` returns only the final result. Use `stream()` for progressive output.
2. **Missing `flush=True` in print** — Without flushing, tokens buffer and appear in chunks.
3. **Ignoring metadata in messages mode** — Use `metadata["langgraph_node"]` to filter which node's tokens to display.
4. **`get_stream_writer()` in async (Python < 3.11)** — Use `writer: StreamWriter` parameter injection instead.
5. **Not using v2 with multiple modes** — Without v2, distinguishing chunk sources is unreliable.
